## 起点：卡片网格的信息效率太低

文章列表页最初复用的是分类页的卡片网格：三列排布，每张卡片里塞标题、日期、分类和描述。看起来整齐，但存在问题：

- 三列并排时，**阅读路径被打断**。眼睛要在三列之间跳跃，而不是顺着一条线往下走。
- 卡片之间靠边框和间距区隔，视觉噪音多，信息密度反而低。
- 分类信息藏在每张卡片内部重复出现，无法形成"同一个分类下有哪些文章"的整体感知。

所以这次改成**单列横向条目流**：左侧分类名，右侧文章条目，每条左文右图。

## 分类左栏：从链接变成标注

最初左栏做成了可点击的分类导航，`position: sticky` 跟随滚动。但实际用起来发现它和右侧内容重复了——点击分类名跳转到分类页，而同一个分类的文章就在右边，跳转反而打断了阅读。

于是左栏退化成**纯标注**：只有分类名和一条竖线。

```
      Kubernetes │  模型越大，为什么还要切 GPU
                 │  一次线上 HPA 频繁扩缩容的排查与参数调优记录
                 │
        个人思考  │  关于技术判断力的一点思考
                 │
```

实现上用两列 Grid，左列固定 132px，分类名右对齐，靠 `border-right` 画出竖线：

```css
.article-cat-group {
    display: grid;
    grid-template-columns: 132px 1fr;
    gap: 28px;
    align-items: start;
}

.article-cat-label {
    position: sticky;
    top: 96px;
    text-align: right;
    border-right: 1px solid rgba(0, 0, 0, 0.08);
    padding-right: 18px;
}
```

分类名是纯文本 `<h2>`，不带链接。竖线把左侧标注和右侧内容框在一起，同一个分类下的多篇文章共享这一条线——这比每篇都标一次分类更经济。

`sticky` 保留下来，因为长列表滚动时，分类名消失会让读者失去位置感。

## 胶囊元信息：每个属性独立可辨

元信息原来是 `2026-11-09 · 24 字 · Kubernetes` 这样用分隔点串成一行。问题在于：

- 分隔点本身是噪音，读者要靠位置来区分字段边界
- 不同性质的字段（时间、数量、标签、地点）视觉权重一样，混在一起
- 深色模式下浅灰文字对比度不足

改成每种属性一个独立胶囊：

```
( 2026-11-09 )  ( 375 字 )  ( Hugo )  ( Shanghai )
```

```css
.article-pill {
    display: inline-flex;
    padding: 2px 10px;
    border-radius: 999px;
    background: #f1f2f4;
    border: 1px solid rgba(0, 0, 0, 0.06);
    font-size: 11px;
    color: #6b7280;
    white-space: nowrap;
}
```

`tcf` 标签用 `--accent` 变体，淡蓝紫底 `#eef1fb`，和普通胶囊区分开——它比日期、字数更"有内容"，值得稍微突出。深色模式下统一换成半透明白底，靠边框而不是背景色来定形。

胶囊的另一个好处是**字段缺失时自然消失**。某篇文章没写 `location`，就少一个胶囊，不会留下空的占位。

## 缩略图：从零到有

改造开始时，所有文章都没有配图，右栏只能放占位块。后来加了一张默认图，并支持按文章覆盖：

```
文章 bundle 内图片 → front matter cover.image → front matter images → 默认图 → 占位块
```

图片用 Hugo 的 `Fill` 裁剪成统一的 320×200：

```go
{{- $thumb = .Fill "320x200 Center" -}}
```

`Fill` 会居中裁掉多余部分。原图 3:2，裁成 16:10 时上下各切掉约 11%——对风景和截图类配图来说，中心区域通常是最重要的部分，所以居中裁切是合理默认。

图片放在 `assets/` 而不是 `content/` 或 `static/`，是因为只有 `assets/` 里的资源才能被 Hugo 的图片处理管道接管。放在 `content/` 下会被当作 section 处理，放在 `static/` 则只能原样引用、无法裁剪。

## 小结

这次重构没有加任何新功能，只是重新分配了信息的位置：

- 分类从"每张卡片内部重复"变为"左侧一次标注"
- 元信息从"一串分隔点"变为"各自独立的胶囊"
- 图片从"没有"变为"按优先级回退的统一缩略图"

布局从三列变两列，真正减少的是读者需要同时追踪的信息源数量。
